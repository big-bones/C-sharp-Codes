Concurrent Programming : It is a conept where basically multiple processes are running simultaneously through context switches
and use of time slice for each process the advantage is that no process is starving and the system is more responsive
Parallel Programming is actually when each process is actually executing on different cores or processors and running 
simultaneously
Thread is a smallest unit of work that can execute independent
Task is abstraction of unit of work that is expected to be ran on a different Thread

Synchronization primiteves are useful to avoid the race conditions when multiple threads are trying to access some shared resource
or critical section
Lock is a synchronization primitive 
Monitor : Monitor.Enter() and Monitor.Exit() need to do exception handling on our own
Sempahore : If a shared resource has multiple instances and multiple threads are trying to access this resource we create sempahore.
If there is an instance of resource that can still be used by a thread Wait() will reduce the count of semaphore
If the count is 0 thread goes in blocking state Release() releases an instance and a thread is removed from blocking state
Mutex is a syncronization primitive that is used when multiple processes are trying to access a shared resource
This is used in inter process synchronization as well as intra process synchornization
Spin locks are non blocking if a thread is already inside critical section and another thread is trying to access the cs
The current thread will not be blocked this is used when the time for which lock is taken is small
Monitor can provide more granular functionality 
ContinueWith is used to chain the tasks
ConfigureAwait is used to preserve the context specially in UI threads after await is executed

REST : These are principles that help in creating networked applications they have certain properties
like stateless meaning that each request provided by the client should have complete information on how to process the request
it also relies on client server architecture which allows them to scale independently
Web API are superset of REST, WebAPI also include other architectural principles like GraphQL or SOAP
API pipeline is basically a series of components through which your request and respone object goes through
Middlewares are components in api pipeline that are executed in the order in which they are defined in Program.cs file
Request and response object goes each middleware 
It can modify the request object and pass it to next middleware
Similary it can modify response object before sending to the client
CORS : Cross Origin Resource Sharing is done to restrict the access for requests outside of domain
We can change the policy to accept from specified domains,specific types of http methods etc
This is done to enhance the security 
API Gateway act as single entry points for all the requests which helps in performing tasks like authentication among other
things
It also helps in load balancing
It can provide security over DDOS attacks by using rate limiters

Stored Procedures and Functions are a set of pre compiled queries stored in the db memory that can be executed as a one unit
Complicated operations can not be done in functions or even transactions
Returns scalar or table
Stored Procedure does not return a value but can have out parameter
Functions can be used in SP or even inside select statement that can be done with stored procedure
Views are basically virtual tables based on the result of some sql query views ideally do not store data unless materialized
They are helpful in abstracting data
We can also add permissions on views increasing the security
Materialized views can store complex operations result and make query faster
Triggers are special types of stored procedures that can be executed instead of a query or after a query
They are helpful in maintaining integrity and maintaining logs etc...
But they have huge overhead
Sometimes a trigger and lead to execution of other triggers making the operations very costly
Also it is difficult to debug in these cases
