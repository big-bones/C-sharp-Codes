Services are injectable objects that provide specific functionality or buisness logic
to other components 
We can make a service available across the application if the provideIn property is set to root
in order to make the service specific to the module or component we need to add it in the
provider array of the specific entities by removing provideIn property in @Injectable
@Input decorator does property binding from parent to child component
@Output marks the property in child component as output event that parent listens to
pass EventEmitter object
-------------------------------------------------------------------------------------------------
Component is a basic building block of the angular application it has HTML , CSS and a TS class
that contains logic and behavior
They are used to define specific UI parts of the application 
They encapsulate the UI and behavior of the application at the smallest level
@Component decorator is used
selector is like an id for each component
-------------------------------------------------------------------------------------------------
Module is essentially a collection of Components , Services that are relevant together
Defined by @NgMoule decorator
imports : refert to other modules this module uses
providers : services it uses
declarations are components inside of the module
bootstrap is the components that should be loaded when application starts

Directives are used to manipulate DOM and extend the functionality of HTML elements
3 type of Directives:
Component is a special kind of directive it is called directive with a view
Structural : They can add or remove the elements from DOM 
*ngFor,*ngIf and *ngSwitch 
Attribute : Make changes to already existing DOM elements(like changing color)
[ngClass] or [ngStyle]
ngStyle makes inline changes
-------------------------------------------------------------------------------------------------
Data binding in angular is used to maintain data consistency across view and the class file 
Interpolation {{}} -> Component -> View
Property Binding [] -> Component -> View
Event Binding () -> View -> Component
Two way binding [(ngModel)] -> View -> Component , Component -> View 
Interpolation only works with string if we need bool values or something it won't work
-------------------------------------------------------------------------------------------------
ngModel is a directive that helps with two way data binding
from DOM to component and from component to DOM
It is a combination of properties and event binding
And the syntax is a combination of both of them
It is a part of FormsModule component 
<input type="text" [(ngModel)] = "username"/>
<h3>This is your username : {{username}} </h3>
ngModel is not used with buttons

Decorators are special function that provide metadata about classes or properties and allow angular
to elements to modify their behavior at runtime
@Input,@Output,@NgModel,@Component,@Injectable
-------------------------------------------------------------------------------------------------
Hooks are methods that run in the life cycle of the component
ngOnChanges() hook is the method that tracks the changes in the input property
input properties in component are specified with @Input decorators
It takes in parameter of type SimpleChanges that can track the previous and current values of
the input decorator that we have mentioned this is useful in passing data from the parent component
to the child component, SimpleChanges is object(probably a JSON object)
-------------------------------------------------------------------------------------------------
ngOnInit() is the hook called only once in the lifecylcle of the component this is called when
the component is fully initialized this method is usually used to set some initial properties
or run some api's to populate initial properties
Why is constructor not used?
Constructor is called when the component is used say a test component is used in app-component
html then the object of test component class is created and constructor is called
but if test-component has some property that is taking data from parent component(app-component)
in this case then this does not work the reason being that the component(test-component)
is not yet fully initialized this is where we use ngOnInit()
ngOnInit() is called once after component is fully initialized 
Any kind of interaction with DOM or setting up @Input properties should be done by ngOnInit()
Constructor is usually used for DI(Dependency Injection)
-------------------------------------------------------------------------------------------------
ngDoCheck() detects every change does not even need to be something with @Input decorator
example say that you have a User object in the parent component that changes just the firstName
not the reference of complete object ngOnChanges() only detects changes to the @Input when
the reference is changed but any kind of change can be detected by ngDoCheck()
Do not use them in the same component (ngDoCheck() and ngOnChanges())
-------------------------------------------------------------------------------------------------
<ng-content> is an angular element that can pass content from parent to child components
@Input can not pass HTML or css that is where this is used
-------------------------------------------------------------------------------------------------
ngAfterContentInit() is used when ever we use <ng-content>
ngAfterContentChecked() is called after every change in the content
ngAfterContentInit() is called only once when the content is passed for the first time not after
that later only ngAfterContentChecked() is called
