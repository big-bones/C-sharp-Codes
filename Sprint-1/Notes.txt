CTS : Common Type System
1.Part of CLR
2.CTS defines how types are declared, used, and managed in the runtime. By providing a standardized type system,        
CTS ensures that objects written in different programming languages can interact with each other, thus   
facilitating cross-language integration and interoperablity
3.For example in VB might define Integer and in C# it can be int but internally they both map to Int32 in CLR

JIT : Just in time Compiler
Just in time compiler is a part of CLR that converts the MSIL code to native code
Just in time compiles the program at runtime for example if a method is invoked
it is compiled and run-time optimized at that time not before 
the optimizations may include unrolling loops , inlining the methods etc..
This converted native code is cached for future use
Types include:
Pre : Compiled before hand 
Ecno : Less optimized code(as and when required)
Normal : More optimized code(as and when required)
JIT has a overhead that normal compilers do not have during runtime which might make program slower

Garbage collection:
The very first step is garbage collector is invoked when there is a shortage of memory for the program
It looks for references that the program can not reach and then it starts to collect them freeing up the memory
The heap area is divided such that there are 3 generations Generation 0 is the place where the Garbage Collector looks
for the stray references initially then it goes to Generation 1 and then Generation 2 the order is such that
Genreation 2 stores the objects that are going to be needed by program in future for long term so they are least frequently collected
After it frees memory it performs compaction to avoid any external fragmentation
We should use Dispose and use GC.SupressFinalize()
destructor is also called Finalizer()
Finalize method call internally all the methods that are available to use Finalize()
