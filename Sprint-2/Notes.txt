IEnumerable is a base interface for all the non-generic collections
IEnumerable<T> is a child of IEnumerable and is a base for all the Generic Collections
ICollection<T> does not directly implement ICollection
Neither does IList<T> directly implement IList
but List<T> implements ICollection<T>,ICollection and IList<T> and IList for backward compatiblity with non-generic
The non-generic interfaces are defined explicitly
ICollection<T> has methods to Add,Remove,properties like Count,ReadOnly...
IList<T> additionaly has a indexer
IDictionary<KeyValuePair<T val,T key>> implements similar ICollection<KeyValuePair<T1 key,T2 value>> and a same IEnumerable interface
These interfcaes do not support Covariance and Contravariance
Queue is independent collectin and does not implement IList or IDictionary interfaces
It implements ICollection<T> and in return IEnumerable<T> and IEnumerable
ISet<T> implements ICollection<T> and in return IEnumerable<T> and IEnumerable
HashSet<T> implements ISet<T> and in return all the methods of precceding interfaces
IComparable<T> has public int CompareTo() method 
ICompare is a non-generic version that takes Object type as a parameter
CompareTo return 1 if you want the current object after the parameter object
CompareTo return -1 if current object is to be before the parameter object
CompareTo return 0 when default ordering is OK
We use IComparer when we want multiple sorting behaviors like maybe not just based on age but also name etc...
since IComparable only provides one way to sort

Reflection
Advantages:Help us inspect metadata including types,methods,properties..etc
this can be useful to create a plugin since we do not know the code structure
Getting information at runtime helps with Logging
When loading something from other source(ex database) for which we do not have complete metadata late binding helps since we can invoke 
types,methods etc at runtime
Disadvantages:Performance overhead and slow because everything happens at runtime.
Security risks since it bypasses the encapsulation and access modifiers
The code does not have support of compile time checking and can lead to issues later and also it is not easy to understand or maintain

Attributes
Attributes are a feature that allows you to add metadata to your code.This metadata can then be retrieved at runtime using reflection. 
Attributes provide a way to associate declarative information with code elements (assemblies, types, methods, properties, etc.) in a manner that is accessible both at compile-time and runtime.
