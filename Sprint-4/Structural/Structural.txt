Structural Patterns are concerned about how classes and objects are composed to form larger structures
It also promotes decoupling using interfaces
-------------------------------------------------------------------------------------------------------------
Adapter:Allows objects with incompatible interfaces to work together and collaberate
Use the Adapter class when you want to use some existing class, but its interface isn’t compatible 
with the rest of your code.
This follows SRP and Open Closed principle
But number of classes increase depdending on new adapters
-------------------------------------------------------------------------------------------------------------
Composite:Defines a common interface to treat the complex and simple objects similarly such that this structure
creates a tree like structure
Use the pattern when you want the client code to treat both simple and complex elements uniformly.
If the classes are not at all similar then we need to make an overgeneralized interface which makes the code 
harder to understand
Follows Open Closed Principle
Actors include : Leaf,Componenet(Interface),Composite
-------------------------------------------------------------------------------------------------------------
Bridge:Bridge let's you split set of closely related classes into two separate hierarchies—
abstraction and implementation—which can be developed independently of each 
When we want to extend the class in independent dimensions
It follows SRP and Open Closed principle
Not similar to abstract factory because it creates objects of classes that work well together not all combinations
like we can have here
-------------------------------------------------------------------------------------------------------------
Facade:It is a structural design pattern that provides a simplified interface to a library, a framework, 
or any other complex set of classes.
If we have a complex subsystem that needs to be used in the program which has multiple classes and corresponding
objects and methods
Facade delegates the client requests to the appropriate objects within the subsystem. The Facade is also responsible
for managing their lifecycle
-------------------------------------------------------------------------------------------------------------
Decorator : Add a functionality at runtime instead of using inheritance we use composition 
Extend the behavior without subclassing
-------------------------------------------------------------------------------------------------------------
